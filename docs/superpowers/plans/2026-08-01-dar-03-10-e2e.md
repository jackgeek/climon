# DAR-03 through DAR-10 E2E Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the cross-platform E2E harness with deterministic DAR-03 through DAR-10 scenarios and descriptive subcheck titles for DAR-01 through DAR-10.

**Architecture:** Keep one isolated runtime and one typed scenario module per DAR ID. Add reusable multi-surface browser, daemon-client, process-discovery, socket-probe, and fixture capabilities; keep platform differences in expectation policy rather than scenario fallbacks.

**Tech Stack:** TypeScript ESM, Bun 1.3.10, Node.js 24, Playwright Chromium, node-pty, `@xterm/headless`, Rust fixtures, Bun test, Cargo test, GitHub Actions.

---

## File Structure

New focused files:

- `harness/src/subchecks.ts` — validates ordered subcheck contracts and constructs titled results.
- `harness/src/drivers/daemon-client.ts` — connects to a session daemon and supports healthy or deliberately stalled clients.
- `harness/src/drivers/process-discovery.ts` — resolves session-host processes and performs platform-specific termination.
- `harness/src/drivers/socket-probe.ts` — verifies loopback and Unix socket listener cleanup.
- `harness/src/scenarios/shared.ts` — scenario-local helpers for deadlines, dependency failures, and deterministic run IDs.
- `harness/src/scenarios/dar-03.ts` through `dar-10.ts` — one orchestration module per DAR contract.
- `harness/fixtures/src/control_probe.rs` — controller/repaint fixture protocol for DAR-03/DAR-04.
- `harness/fixtures/src/metadata_probe.rs` — attention/title/progress fixture protocol for DAR-05/DAR-06.
- `harness/fixtures/src/lifecycle_probe.rs` — exit, flood, and signal-hold protocols for DAR-07 through DAR-10.
- Matching focused tests under `harness/tests/`.

Existing files modified:

- `harness/src/types.ts`, `scenario-registry.ts`, `cli.ts`, reporters, and existing DAR modules for titled subchecks and dispatch.
- `harness/src/drivers/browser.ts` for multiple surfaces and semantic dashboard assertions.
- `harness/src/runtime-supervisor.ts` only where multiple browser contexts or runtime evidence must be owned and cleaned.
- `harness/fixtures/src/{cli,lib}.rs` for public fixture command registration.
- `.github/workflows/e2e-harness.yml`, harness documentation, feature catalogue, and manual-test index for the complete suite.

- [ ] **Step 3: Add the typed contract implementation**

Implement:

```ts
export interface SubcheckDefinition<Name extends string = string> {
  name: Name;
  title: string;
}

export interface SubcheckResult {
  name: string;
  title: string;
  status: SubcheckStatus;
  durationMs: number;
  message?: string;
  evidence?: string[];
}

export function validateSubcheckResults(
  definitions: readonly SubcheckDefinition[],
  results: readonly SubcheckResult[]
): void {
  if (definitions.length !== results.length) {
    throw new HarnessError("assertion", `Expected ${definitions.length} subchecks, received ${results.length}`);
  }
  definitions.forEach((definition, index) => {
    const result = results[index];
    if (result.name !== definition.name) {
      throw new HarnessError("assertion", `Subcheck order mismatch at ${index}: expected ${definition.name}, received ${result.name}`);
    }
    if (result.title !== definition.title) {
      throw new HarnessError("assertion", `Subcheck title mismatch for ${definition.name}`);
    }
  });
}
```

Declare `DAR_01_SUBCHECKS` and `DAR_02_SUBCHECKS` as ordered objects, update constructors to copy titles, validate before outcome comparison, and update all reporters.
